## 미결정 사항 (다음 단계를 시작하기 전에 정할 것)

### D1. 거리 척도 — 셋 중 무엇을 기준으로 삼는가

| 척도 | 재는 것 | 함정 |
|---|---|---|
| Frobenius `‖[A\|b] − [A'\|b']‖_F` | 파라미터 공간 유클리드 거리 | 큰 성분이 지배. 스케일 민감 |
| row-wise cosine | 클래스별 판단 "방향"의 각도 | 크기 정보를 버림 |
| logit 차이 `E_x‖(A−A')x + (b−b')‖` | 실제 행동 차이 | 데이터 분포 의존 |

**적어둔 예측 (concepts.md §1.5):** 제약조건이 `err(⟦P⟧, f_θ) ≤ ε` 이므로
ε을 재는 방식과 일관된 거리는 **logit 차이**다. 따라서 같은 K에서
logit 거리가 가장 낮은 오차를 낼 것이고 Frobenius가 가장 보수적일 것이다.
**아직 검증 안 됨.**

### D2. 클러스터링 알고리즘

K-means는 유클리드 거리 전용이라 cosine·logit 거리에 그대로 못 쓴다.
세 척도를 **공정하게** 비교하려면 셋 다 받아들이는 알고리즘이 필요하다.
→ agglomerative (average linkage)가 유력. Ward는 유클리드 전용이라 제외.
단, agglomerative는 O(R²) 메모리라 MNIST에서 문제 (아래 D3).

### D3. MNIST 규모 문제

고유 영역 60,000개.
- `[A_r|b_r]` 전체 = 1.9 GB
- 쌍거리 행렬 = 60000² = 36억 개 → **계산 불가**

서브샘플링이 필요하다. 그런데 서브샘플링은 결과 해석을 바꾼다:
"6만 개 영역을 K개로 줄였다"가 아니라 "표본 M개를 K개로 줄였다"가 된다.
**M을 얼마로 할지, 그리고 그게 Ω(ε) 곡선 해석에 무엇을 의미하는지 먼저 정한다.**

### D4. ε을 무엇으로 재는가

정확도 하락 / logit L2 / KL divergence — 셋이 다른 곡선을 준다.
- 정확도: 해석이 직관적이지만 계단형이라 곡선이 거칠다
- logit L2: 부드럽지만 "얼마나 나쁜지" 감이 안 온다
- KL: 확률 분포로서의 차이. 이론적으로 깔끔

**둘 이상을 같이 그리는 것이 안전할 듯.** 결정 필요.

## 겪은 실패와 교훈

### L1. 퇴화(degenerate) 예시로 개념을 설명하려다 틀렸다

`scripts/walkthrough.py` STEP 3에서 "유닛 3개면 조각 7개"를 보이려고
세 직선 `x₁=0, x₂=0, x₁+x₂=0` 을 골랐는데 **6개가 나왔다.**
세 직선이 전부 원점을 지나서(concurrent) 일반위치가 아니었기 때문.

**교훈:** `1+h+C(h,2)` 는 **상한**이고 등호는 일반위치에서만 성립한다.
교육용 예시를 만들 때 우연히 대칭적/퇴화 케이스를 고르기 쉽다.
→ 지금은 일반위치(`x₁+x₂=1`)와 퇴화(`x₁+x₂=0`)를 **둘 다** 보여주도록 고쳤다.
오히려 더 좋은 설명이 됐다.

### L2. `A_r`만으로는 부족하다 — 절편을 빼먹으면 안 된다

프로젝트 개요에 `A_r = W2·D1(r)·W1` 만 적혀 있었지만
실제로는 `b_r = W2·D(r)·b1 + b2` 가 함께 나온다.
`A_r`만으로 클러스터링하면 **기울기는 같은데 절편이 다른** 서로 다른 함수를
하나로 합쳐버린다. 거리는 반드시 증강 행렬 `[A_r | b_r]` 위에서.

### L3. "경계가 꺾인다"를 "영역이 휘어진다"로 오해하기 쉽다

깊은 ReLU 망에서도 **영역 자체는 항상 볼록 다면체**다.
패턴을 고정하면 각 유닛의 제약이 `x`에 대해 선형이 되기 때문.
꺾이는 것은 *한 유닛의 영점 집합*이라는 전역적 대상이고,
볼록한 것은 *한 영역*이라는 국소적 대상 — 층위가 다르다.
→ 이걸 확인하려고 만든 **선분 볼록성 테스트가 예상 밖의 수확**이었다 (아래 I1).

### L4. 시스템 파이썬이 3.14 하나뿐이었다

Ubuntu 26.04에 Python 3.14만 있고 uv/conda/pipx 전무.
연구 레포(param-decomp 등)는 보통 3.11~3.12를 핀으로 박는다.
→ uv로 3.12 전용 환경 분리. **시스템 파이썬은 건드리지 않는다.**

## 영감 / 쫓아볼 만한 관찰

### I1. 선분 볼록성 테스트는 차원 무관 도구다 ★

"볼록 집합 ∩ 직선 = 하나의 구간" 이라는 사실만 쓰므로
**폴리토프를 그릴 수 없는 784차원에서도 그대로 돈다.**
부수적으로 얻은 값: **MNIST에서 데이터 두 점을 잇는 직선이 평균 63개 영역을 지난다**
(2D는 19~26개). 그림 없이 영역 밀도를 재는 방법.

→ 이 아이디어를 확장할 여지: 선분 위 `A_r`의 변화율을 재면
"이 방향으로 모델이 얼마나 급격히 다르게 계산하는가"를 측정할 수 있다.
Stage 5(a) 개입 실험의 사전 도구가 될 수 있음.

### I2. spiral에서 깊이 효과가 크게 나왔다

유닛 수가 64로 같은데 1층 95.5% vs 2층 100.0%.
2D·64유닛으로는 직선 arrangement만으로 나선을 감싸기 어렵다는 뜻.
→ **깊이 축이 단순한 통제 변수가 아니라 그 자체로 볼거리일 수 있다.**
ε-path가 1층/2층에서 다른 모양으로 나오면 그게 결과다.

### I3. MNIST R/N = 1.000 의 함의는 생각보다 무겁다

입력 6만 개 = 영역 6만 개. 즉 MNIST에서 "영역 클러스터링"은
**"데이터 포인트 클러스터링"과 구분되지 않는다.**
→ Stage 1이 MNIST에서 재는 Ω는 함수의 성질이 아니라 **함수 + 데이터 분포**의 성질.
→ 2D(R/N ≈ 0.11~0.19)에서는 영역이 데이터와 독립적 의미를 가짐.
**두 세팅을 모두 쓰는 실질적 근거가 이것이다.** 처음엔 그냥 "쉬운 것부터"였지만
이제 숫자로 된 이유가 있다.

## 열린 질문

### Q1. Stage 1의 Ω는 하한이다 — 라우팅 비용을 언제 청구할 것인가

`⟦P⟧(x) = A_{k(x)}·x + b_{k(x)}` 를 실행하려면 `k(x)`를 알아야 하고,
`k(x)`를 알려면 **원본 네트워크의 첫 층을 돌려야 한다.**
즉 Stage 1의 설명은 신경망을 오라클로 호출하며, 자립적이지 않다.

정직하게는 `Ω(P) = K + Ω(라우팅 규칙)`.
Stage 5(c)가 그 정산 자리로 설계돼 있지만, **Stage 1 단계에서 라우팅 복잡도의
하한이라도 재둘 수 있는지** 생각해볼 것 (예: 클러스터를 분리하는 데 필요한
초평면의 최소 개수).

### Q2. Stage 4가 실패할 때 두 가지 실패를 구분할 수 있는가

SPD 컴포넌트는 **파라미터 공간**, polytope 클러스터는 **입력 공간**.
단위가 달라 직접 비교가 안 된다. 매개가 필요하다 —
각 입력에서 "활성 컴포넌트 집합"과 "클러스터 라벨"을 뽑아 상호정보량을 보는 식.

실패 시 두 경우를 구분해야 한다:
(a) 대응이 실제로 없다  (b) 대응을 재는 방법이 틀렸다
→ **(b)를 배제할 수 있는 sanity check를 미리 설계해둘 것.**
예: 인위적으로 대응이 있는 toy 상황을 만들어 측정법이 그걸 잡아내는지 확인.

### Q3. 정규화가 ε-path를 낙관적으로 만드는가

`train_model`의 `weight_decay` 기본값을 0으로 뒀다.
"전형적으로 학습된 MLP"를 얻는 게 목적이고, 정규화를 걸면 폴리토프 구조가
인위적으로 단순해져 ε-path가 좋아 보일 수 있다는 우려 때문.
→ 이건 **가설이지 검증된 게 아니다.** 나중에 별도 축으로 확인해볼 가치가 있다.

### Q4. 격자 실측이 공식보다 작은 것은 상자 때문만인가

h=4에서 실측 10 vs 공식 11, h=16에서 96 vs 137, h=32에서 369 vs 529.
격차가 h에 따라 커진다. 상자(±3.5) 절단 때문이라고 설명했지만
**학습된 가중치가 완전한 일반위치가 아닐 가능성**도 있다
(학습이 유닛들을 정렬시켜 부분적으로 퇴화 배치를 만들 수 있음).
→ 상자를 키워가며 수렴하는지 보면 구분된다. 아직 안 해봤다.

## 왜 이걸 하는가 — 먼저 목적지부터

우리가 하려는 건 결국 이겁니다:

> **학습된 MLP를 보고 "이건 이런 계산을 한다"고 말할 수 있게 되는 것.**

그런데 MLP를 그냥 보면 가중치 숫자 덩어리라 말할 게 없습니다.
그래서 **말할 수 있는 형태로 바꿔야** 합니다. 그 형태가 이것입니다:

```
입력 x 가 들어오면
    1. x 가 어느 "구역"에 속하는지 본다
    2. 그 구역에 적힌 행렬 A 를 꺼내서 A·x + b 를 계산한다
```

이건 **완전히 이해 가능한 계산**입니다. 구역별 조견표(lookup table)일 뿐이니까요.
그리고 놀랍게도 **ReLU MLP는 정확히 이렇게 생겼습니다** — 근사가 아니라 정확히.

문제는 구역이 몇 개냐입니다. 구역이 5개면 우리는 이 MLP를 완전히 이해한 겁니다.
구역이 6만 개면 조견표가 원본만큼 크니까 아무것도 이해 못 한 겁니다.

**그래서 Stage 1의 질문은 하나입니다: 구역을 몇 개까지 줄일 수 있는가?**

아래는 이 구조가 왜 성립하는지, 구역이 실제로 몇 개인지를 한 걸음씩 확인하는 과정입니다.

---

## STEP 1 — ReLU 유닛 하나 = 칼질 한 번

유닛 하나는 이렇게 생겼습니다:

```
z(x) = w·x + b
출력 = ReLU(z) = max(0, z)
```

구체적으로 `w = [1, 0]`, `b = -0.5` 를 넣으면 `z(x) = x₁ - 0.5` 입니다.

| x | z = x₁ − 0.5 | r = 1[z>0] | ReLU(z) |
|---|---|---|---|
| (0, 0) | −0.50 | 0 | 0.00 |
| (1, 0) | 0.50 | **1** | 0.50 |
| (0, 5) | −0.50 | 0 | 0.00 |
| (2, −3) | 1.50 | **1** | 1.50 |

**읽는 법.** `x₂`는 `z`에 전혀 영향이 없습니다 (`w`의 둘째 성분이 0이니까).
그래서 켜짐/꺼짐 경계는 `x₁ = 0.5`라는 **세로 직선 하나**입니다.

> **유닛 하나 = 평면을 두 조각으로 나누는 칼질 한 번.**
> `w`가 칼날의 방향을 정하고, `b`가 칼질의 위치를 정합니다.

여기서 `r = 1[z>0]` 이 **활성 비트**입니다. 유닛이 켜졌으면 1, 꺼졌으면 0.
유닛이 h개면 h비트짜리 벡터가 나오고, 그게 **활성 패턴** 또는 **코드**입니다.

---

## STEP 2 — 유닛 2개, 그리고 "행렬 하나"가 튀어나오는 순간

이제 유닛 2개짜리 신경망을 손으로 계산합니다.

```
W1 = [[1, 0],      b1 = [-0.5, -0.5]      유닛0 경계: x₁ = 0.5
      [0, 1]]                             유닛1 경계: x₂ = 0.5
W2 = [[2, 3]],     b2 = [1.0]
```

두 칼질이 평면을 **4조각**으로 나눕니다. 각 조각에서 무슨 일이 일어나는지 봅시다.

| 조각 (코드) | 예시 x | A_r | b_r | 검산 |
|---|---|---|---|---|
| (0,0) 둘 다 꺼짐 | (0, 0) | [0, 0] | 1.00 | 1.00 = 1.00 ✓ |
| (1,0) 유닛0만 | (2, 0) | [2, 0] | 0.00 | 4.00 = 4.00 ✓ |
| (0,1) 유닛1만 | (0, 2) | [0, 3] | −0.50 | 5.50 = 5.50 ✓ |
| (1,1) 둘 다 | (2, 2) | [2, 3] | −1.50 | 8.50 = 8.50 ✓ |

**어떻게 이 A_r이 나왔는가 — 손으로 따라가기.**

코드 `(1,0)`인 조각을 봅시다. 유닛0은 켜졌고 유닛1은 꺼졌습니다.
꺼진 유닛의 출력은 **항상 0**이므로, 그 유닛은 최종 출력에 아무 기여도 못 합니다.

```
출력 = W2 · [ReLU(z₀), ReLU(z₁)] + b2
     = [2, 3] · [z₀, 0] + 1          ← 유닛1이 꺼졌으니 둘째 자리는 0
     = 2·z₀ + 1
     = 2·(x₁ − 0.5) + 1
     = 2·x₁ + 0                       ← A_r = [2, 0], b_r = 0
```

이걸 행렬로 쓰면 `A_r = W2 · D(r) · W1` 이고, `D(r) = diag(1, 0)` 입니다.
`D`를 곱하는 것은 **꺼진 유닛에 해당하는 W2의 열을 지우는 것**과 같습니다.

> ★ **ReLU는 정보를 "자르는" 게 아니라 `W2`의 "열을 골라내는 스위치"입니다.**
> 켜진 유닛에 해당하는 열만 최종 선형맵에 기여합니다.
> 코드 `(1,0)`이면 0번 열 `[2]`만, `(0,1)`이면 1번 열 `[3]`만,
> `(1,1)`이면 둘 다 `[2,3]`, `(0,0)`이면 아무것도 안 남아서 상수 함수.

**이게 Stage 1 전체의 기반입니다.** 코드를 알면 ReLU가 사라지고 행렬 하나만 남습니다.

## STEP 3 — 유닛 3개면 조각이 8개? 아니요, 7개입니다

여기가 대부분이 헛디디는 지점입니다.

코드가 3비트니까 `2³ = 8`가지가 있을 것 같습니다. 실제로 세어봅시다.

세 직선: `x₁ = 0`, `x₂ = 0`, `x₁ + x₂ = 1`

| 코드 | 실현 가능? |
|---|---|
| (0,0,0) | O |
| **(0,0,1)** | **X ← 불가능** |
| (0,1,0) | O |
| (0,1,1) | O |
| (1,0,0) | O |
| (1,0,1) | O |
| (1,1,0) | O |
| (1,1,1) | O |

**7개 / 8개.** 왜 `(0,0,1)`은 불가능한가 — 그냥 산수입니다:

```
(0,0,1) 이 요구하는 것:  x₁ ≤ 0  이고  x₂ ≤ 0  인데  x₁ + x₂ > 1
x₁ ≤ 0 이고 x₂ ≤ 0 이면  x₁ + x₂ ≤ 0.  1보다 클 수 없다.  모순.
```

반면 `(1,1,0)`은 가능합니다: `x = (0.2, 0.2)` → `x₁>0, x₂>0, x₁+x₂ = 0.4 < 1`. OK.

> ★ **코드는 3비트지만 기하학적으로 실현 가능한 코드는 더 적습니다.**
> 평면이 좁아서 직선들이 서로를 제약하기 때문입니다.

### 그런데 여기 함정이 하나 더 있습니다

셋째 직선을 `x₁ + x₂ = 1` 대신 `x₁ + x₂ = 0` 으로 바꾸면 조각이 **6개**가 됩니다.
이제 세 직선이 전부 원점을 지나기 때문입니다 (concurrent).
한 점에서 만나는 세 직선은 평면을 부채꼴 6개로 가릅니다 — 교점이 3개가 아니라 1개로 뭉쳤죠.

그래서 정확히 말하면:

```
조각 수  ≤  1 + h + C(h, 2)        (2차원의 경우)
```

**등호는 "일반위치(general position)"에서만** 성립합니다.
일반위치 = 세 직선이 한 점에서 만나지 않고, 두 직선이 평행하지도 않음.
학습된 가중치는 거의 항상 일반위치라 실무에서는 등호에 가깝습니다.
(STEP 4에서 실제 학습된 모델도 h=3일 때 정확히 7이 나옵니다.)

## STEP 4 — 유닛을 늘려보기: 2^h는 완전히 틀린 직관

실제 학습된 `moons h=[64]` 모델의 첫 층에서, 앞에서부터 h개만 켜고 조각을 셉니다.

| h | 실측 조각수 | 2^h | 공식 `1+h+C(h,2)` |
|---|---|---|---|
| 1 | 2 | 2 | 2 |
| 2 | 4 | 4 | 4 |
| **3** | **7** | **8** | **7** ← 여기서 처음 벌어짐 |
| 4 | 10 | 16 | 11 |
| 5 | 13 | 32 | 16 |
| 8 | 33 | 256 | 37 |
| 16 | 96 | 65,536 | 137 |
| 32 | 369 | 4,294,967,296 | 529 |
| **64** | **1,378** | **1.8 × 10¹⁹** | **2,081** |

그림: `artifacts/figures/walkthrough_buildup.png`

**읽는 법.**
- `h=1,2`까지는 `2^h`와 같습니다. `h=3`에서 처음 벌어집니다.
- `h=64`에서 `2^h`는 1.8경인데 실제 조각은 **2천 개 남짓**. 16자릿수 차이입니다.
- **"코드가 64비트니까 영역이 2⁶⁴개"는 완전히 틀린 직관입니다.**

실측이 공식보다 조금 작은 이유: 우리는 `±3.5` 상자 안만 셌습니다.
상자 밖에서만 나타나는 조각들이 빠졌습니다. 상자를 키우면 공식에 수렴합니다.

**여기까지의 결론: 2D에서는 조각이 2천 개 남짓. 다룰 만합니다.**

## STEP 5 — 그런데 MNIST에서는 왜 다시 2^128이 되는가

일반 공식은 이렇습니다 (d = 입력 차원):

```
조각 수  ≤  Σ_{i=0}^{min(d, h)} C(h, i)
```

합의 범위가 **`i = 0 .. min(d, h)`** 라는 데 주목하세요. 여기서 모든 게 갈립니다.

| 세팅 | d | h | 상한 |
|---|---|---|---|
| 2D 합성 | 2 | 64 | `1 + 64 + 2016` = **2,081** |
| MNIST | 784 | 128 | `Σ_{i=0}^{128} C(128,i)` = **2^128 ≈ 3.4 × 10³⁸** |

- `d=2`면 합이 **세 항에서 끊깁니다** (`i = 0, 1, 2`). 그래서 h에 대해 2차식.
- `d=784`면 `h=128 ≤ d` 이므로 합이 **끝까지** 갑니다. 이항정리로 정확히 `2^128`.
  상한이 "모든 코드가 가능하다"가 되어 아무 정보가 없습니다.

**직관.** STEP 3에서 코드가 제약된 이유는 **2차원 평면이 좁아서** 직선들이
서로를 밀어냈기 때문입니다. 784차원에서는 128개 초평면이 서로를 **전혀 제약하지 않습니다** —
공간이 남아돕니다. 모든 부호 조합이 실현됩니다.

> ★ 그래서 우리가 실측한 **MNIST의 R/N = 1.000** (입력 6만 개 = 영역 6만 개)은
> 이상한 결과가 아니라 **당연한 결과**입니다.
> 그리고 이건 Stage 1의 출발점이 `K = 60,000` 이라는 뜻입니다.

## 그래서 지금 우리는 어디에 있는가

여기까지 확인한 것을 목적지와 연결하면:

```
목표:  x -> 구역 찾기 -> 그 구역의 A 로 A·x + b

확인:  ★ 이 구조가 정확히 성립한다        (검산 max_rel_err ~ 1e-6, 6개 모델 전부)
       ★ 구역은 항상 볼록 다면체다         (784차원에서도 위반 0)
       ★ 2D:    구역 약 1,400개 (데이터 위에서는 350~600개)
       ★ MNIST: 구역 60,000개 = 데이터 개수와 같음
```

**조견표가 6만 줄이면 이해한 게 아닙니다.** 원본 신경망 파라미터가 약 10만 개인데
조견표는 6만 줄 × 7,850 숫자니까 오히려 더 큽니다.

그래서 다음 질문이 자동으로 나옵니다:

> **비슷한 A를 가진 구역들을 합쳐서, 조견표를 몇 줄까지 줄일 수 있는가?
> 그리고 그렇게 줄였을 때 원본과 얼마나 달라지는가?**

앞의 것이 **Ω** (조견표 줄 수), 뒤의 것이 **ε** (오차)입니다.
`K`를 줄이면 `ε`이 커지고, 그 맞바꿈 곡선이 **ε-path**입니다.

```
ε (오차)
 │
 │  K=1 (전부 하나로 합침. 그냥 선형 모델)
 │  ●
 │   ╲
 │    ╲
 │     ●  K=10
 │      ╲___
 │          ●────●────●  K=100, 1000, 60000
 │                        (K=60000 이면 ε=0. 원본과 동일)
 └──────────────────────► K = Ω (조견표 줄 수)
```

이 곡선이 **왼쪽에서 빨리 바닥에 닿으면** = 적은 줄로도 원본을 재현 = 이해 가능한 모델.
**오른쪽 끝까지 안 떨어지면** = 줄일 수 없음 = 이 모델의 계산은 압축되지 않음.

Stage 3(modular addition)이 필요한 이유가 여기 있습니다.
"왼쪽에서 빨리 떨어지는 곡선"이 실제로 어떻게 생겼는지 본 적이 없으면,
Stage 1의 곡선이 좋은 건지 나쁜 건지 판단할 기준이 없습니다.

## 다음 단계에서 결정해야 할 것들

곡선을 그리려면 두 가지를 정해야 하고, 둘 다 자명하지 않습니다.

**1. "비슷한 A"의 비슷함을 어떻게 재는가**

| 척도 | 재는 것 | 함정 |
|---|---|---|
| Frobenius | 행렬 성분의 차이 제곱합 | 큰 성분이 거리를 지배 |
| row-wise cosine | 클래스별 판단 "방향"의 각도 | 크기 정보를 버림 |
| logit 차이 | 실제 출력이 얼마나 다른가 | 데이터 분포에 의존 |

**2. ε을 무엇으로 재는가** — 정확도 하락? logit L2 거리? KL divergence?
셋이 서로 다른 곡선을 줍니다.

그리고 MNIST에서는 규모 문제가 있습니다. 6만 개 구역의 쌍거리 행렬은
`60000²  = 36억` 개라 계산이 불가능합니다. 서브샘플링이 필요하고,
그게 결과 해석에 무엇을 의미하는지 미리 정해둬야 합니다.

# 핵심 개념 정리

이 문서는 프로젝트 전체에서 쓸 개념들을 코드보다 **먼저** 정리한 것이다.
Part 1은 Stage 1에서 당장 필요하므로 깊게, Part 3~4는 해당 단계에서 다시 확장한다.

---

## Part 0. 문제 설정

### 0.1 우리가 푸는 최적화 문제

    P* = argmin Ω(P)   s.t.   err(⟦P⟧, f_θ) ≤ ε

말로 풀면: **"오차 ε까지는 봐준다고 할 때, 이 신경망을 설명하는 가장 단순한 설명은 무엇이고
그 단순함은 얼마나 되는가?"**

네 기호가 각각 무엇인지 확실히 해두자. 이게 흐려지면 이후 모든 단계가 흐려진다.

| 기호 | 정체 | 주의점 |
|---|---|---|
| `f_θ` | 학습된 신경망. 파라미터 θ가 박혀 있는 구체적 함수 | 아키텍처가 아니라 **학습이 끝난 특정 가중치** |
| `P` | 설명. 사람이 읽거나 실행할 수 있는 대상 | 자연어가 아니라 **형식적 객체**여야 한다 (클러스터 표, 컴포넌트 집합, 의사코드) |
| `⟦P⟧` | P를 실행했을 때 나오는 함수 | P가 "설명"으로 기능하려면 반드시 **실행 가능**해야 한다 |
| `Ω(P)` | P의 복잡도 | 숫자여야 한다. 무엇을 셀지가 각 Stage의 설계 결정 |
| `ε` | 허용 오차 | 스칼라 하나가 아니라 **곡선을 그리기 위한 축** |

### 0.2 ε-path: 이게 진짜 산출물이다

ε 하나를 고정하고 Ω 하나를 얻는 게 목표가 아니다. ε을 움직이면서
**Ω(ε) 곡선 전체**를 그리는 것이 목표다. 이 곡선을 `ε-path`라 부르자.

```
Ω(ε)
 │
 │╲                     (A) 급격히 꺾임 = 구조가 있다.
 │ ╲                        조금만 오차를 봐주면 설명이 확 단순해진다.
 │  ╲___                    → "이 모델은 알고리즘을 배웠다"
 │      ╲___
 │──────────╲______
 │
 │────────────────       (B) 완만함 = 압축이 안 된다.
 │ ╲__                       오차를 많이 봐줘도 설명이 별로 안 줄어든다.
 │     ╲__                   → "이 모델의 계산은 대부분 알고리즘적이지 않다"
 └──────────────────► ε
```

**곡선이 (B)로 나오는 것도 결과다.** 실패가 아니다.
다만 (A)와 (B)를 구분하려면 (A)가 확실히 나오는 대조군이 있어야 하고,
그게 Stage 3(modular addition)이 존재하는 이유다.

### 0.3 simulation relation — 왜 입출력 일치로는 부족한가

`⟦P⟧(x) = f_θ(x)`가 모든 x에서 성립하면 설명으로 충분한가? **아니다.**

극단적 반례: `P = "θ를 그대로 적어놓은 표"`. 이건 완벽하게 입출력이 일치하지만
아무것도 설명하지 않는다. 이 경우 Ω가 크므로 argmin에서 걸러진다.

더 위험한 반례: 우연히 같은 출력을 내지만 **전혀 다른 방식으로 계산하는** 설명.
데이터 분포 위에서만 맞고 조금만 벗어나면 깨진다. 이건 Ω가 작을 수도 있어서
argmin으로 걸러지지 않는다. 그래서 추가 조건이 필요하다.

**simulation relation**: 추상화 함수 `α`가 존재해서,
f_θ의 내부 상태를 P의 내부 상태로 보내고, 그 대응이 계산 과정 내내 유지되는 것.

```
        f_θ의 내부 상태  ──(f_θ의 한 스텝)──►  f_θ의 내부 상태
              │                                      │
            α │                                    α │      ← 이 사각형이 닫혀야 한다
              ▼                                      ▼
        P의 내부 상태   ──( P의 한 스텝 )──►   P의 내부 상태
```

이 프로젝트에서 α가 구체적으로 무엇이 되는지:

| Stage | f_θ의 내부 상태 | α | P의 내부 상태 |
|---|---|---|---|
| 1 | 활성 패턴 `r(x)` ∈ {0,1}^h | 클러스터 할당 | 클러스터 라벨 `k` |
| 2 | 레이어별 activation | 컴포넌트 활성 지시자 | 활성 컴포넌트 집합 |
| 3 | hidden 벡터 | 푸리에 변환 | 주파수별 (cos, sin) 성분 |

Stage 1을 예로 들면: "출력이 비슷하다"가 아니라
**"입력 x에 대해 원 모델이 쓰는 affine 맵과, 설명이 고른 클러스터의 대표 affine 맵이
대응한다"** 는 것까지 요구한다는 뜻이다.

## Part 1. ReLU MLP는 piecewise-linear 함수다 (Stage 1)

### 1.1 활성 패턴 (activation pattern / binary code)

hidden layer 1개짜리 ReLU MLP:

    z(x) = W1·x + b1        z ∈ R^h        (pre-activation)
    a(x) = ReLU(z(x))                      (post-activation)
    f(x) = W2·a(x) + b2                    (logits)

`ReLU(z) = max(0, z)`는 **각 유닛마다 독립적으로** "켜짐/꺼짐"을 결정한다.
입력 x에 대해 어떤 유닛들이 켜졌는지를 h비트 벡터로 적은 것이 **활성 패턴**이다.

    r(x) = 1[z(x) > 0]  ∈ {0,1}^h

이게 "binary code"다. 유닛이 128개면 128비트짜리 코드가 입력마다 하나씩 나온다.

### 1.2 활성 패턴을 고정하면 ReLU가 사라진다

핵심 관찰: **r을 알면 ReLU는 선형 연산이 된다.**

`D(r) = diag(r)` — 켜진 유닛 위치에 1, 꺼진 유닛 위치에 0인 대각행렬.
r(x) = r인 입력 x에 대해서는:

    ReLU(z) = D(r)·z        (곱셈 하나. 비선형성 없음)

따라서

    f(x) = W2·D(r)·(W1·x + b1) + b2
         = [W2·D(r)·W1]·x + [W2·D(r)·b1 + b2]
         =        A_r      ·x +          b_r

**이게 Stage 1 전체의 출발점이다.** 활성 패턴 r을 고정하면 신경망은
그냥 하나의 affine 변환 `x ↦ A_r·x + b_r`이 된다.

> ⚠️ **offset을 빼먹지 말 것.** 프로젝트 개요에는 `A_r = W2·D1(r)·W1`만 적혀 있지만
> 실제로는 `b_r = W2·D(r)·b1 + b2`라는 절편이 함께 나온다.
> 두 영역이 **기울기는 같은데 절편이 다를** 수 있으므로,
> 클러스터링은 A_r만이 아니라 **증강 행렬 `[A_r | b_r]`** 로 해야 한다.
> A_r만 쓰면 서로 다른 함수를 같은 것으로 합쳐버린다.

차원 확인 (MNIST, h=128, 10클래스):
- `W1`: 128×784, `W2`: 10×128
- `A_r = W2·D(r)·W1` : **10×784** — 각 행이 784차원 = **28×28 이미지로 볼 수 있다**
- `b_r` : 10
- 증강 `[A_r | b_r]` : 10×785

`A_r`의 c번째 행을 28×28로 reshape하면 **"이 영역에서 모델이 클래스 c를 판단하는 데
쓰는 템플릿"** 이다. 784차원인데도 직관이 살아있는 이유가 이것이다.

### 1.3 영역(region)은 다면체(polytope)다

`r(x) = r`인 입력들의 집합은 어떻게 생겼나? 각 유닛 i에 대해

    r_i = 1  ⟺  (W1의 i번째 행)·x + b1_i > 0     ← 반공간(halfspace) 하나
    r_i = 0  ⟺  (W1의 i번째 행)·x + b1_i ≤ 0     ← 반대쪽 반공간

즉 영역 = **h개 반공간의 교집합** = 볼록 다면체(convex polytope).
그리고 입력 공간 전체는 이 다면체들로 빈틈없이 타일링된다.

**hidden 1층에서 경계는 전부 전역 초평면이다.** `W1`의 각 행이 초평면 하나를 정의하고,
그 h개 초평면이 공간을 자른다 (hyperplane arrangement).

**hidden 2층이 되면 유닛의 영점 집합이 꺾인다.** 둘째 층의 pre-activation은
`W2·D(r¹)·W1·x + ...` 이므로 그 부호 경계가 **첫 층 영역마다 다른 초평면**이 된다.
즉 둘째 층 유닛 하나의 `z=0` 면은 입력 공간 전체에서 보면
첫 층 경계에서 접히는 조각별 초평면(piecewise hyperplane)이다.

```
   hidden 1층                    hidden 2층
   ─────────────                 ─────────────
   유닛 하나의 z=0:              유닛 하나의 z=0:

        ╱                             ╱
       ╱                             ╱
      ╱                          ───╱          ← 첫 층 경계를 지나며
     ╱                          ╱                 기울기가 바뀐다
    ╱                          ╱
   전역 직선 하나              꺾인 조각별 직선
```

> ⚠️ **혼동 주의 — 영역 자체는 깊이와 무관하게 항상 볼록이다.**
>
> "경계가 꺾인다"를 "영역 모양이 휘어진다"로 읽으면 안 된다.
> 활성 패턴을 고정하면 **각 유닛의 제약이 x에 대해 선형**이 되므로
> (upstream이 전부 선형이 되니까), 영역은 여전히 반공간들의 교집합 = **볼록 다면체**다.
> 깊은 ReLU 망에서도 마찬가지다.
>
> 꺾이는 것은 *한 유닛의 영점 집합*이라는 전역적 대상이고,
> 볼록한 것은 *한 영역*이라는 국소적 대상이다. 둘은 다른 층위의 얘기다.
>
> **볼록성 검증법 (차원 무관):** 볼록 집합과 직선의 교집합은 항상 하나의 연결된 구간이다.
> 따라서 입력 공간에 선분을 긋고 그 위를 촘촘히 걸으며 활성 패턴을 기록하면
> **어떤 패턴도 두 번 나타나서는 안 된다.** 한 번 떠난 영역으로 되돌아오면 볼록이 아니다.
> 이 테스트는 2D뿐 아니라 MNIST의 784차원에서도 그대로 돈다 —
> 폴리토프를 그릴 수 없는 곳에서 구조를 검증하는 첫 도구다.

이 차이 때문에 **깊이 축이 강력한 일반성 검증**이 된다.
"직선 경계라서 우리 프로토콜이 돌아갔던 것"이 아님을 보이려면 2층에서도 돌려봐야 한다.

### 1.4 영역은 셀 수 없다 — 그래서 우리는 샘플링한다

⚠️ **이건 Stage 1에서 가장 오해하기 쉬운 지점이다.**

입력 차원 d, hidden 유닛 h개인 1층 ReLU MLP의 영역 개수 상한 (Zaslavsky):

    R(h, d) ≤ Σ_{i=0}^{d} C(h, i)

숫자를 넣어보면:

| 세팅 | d | h | 영역 개수 상한 | 열거 가능? |
|---|---|---|---|---|
| **2D 합성** | 2 | 64 | 1 + 64 + 2016 = **2081** | ✅ **가능** |
| **MNIST** | 784 | 128 | h ≤ d 이므로 사실상 **2^128** | ❌ 원천 불가 |

즉 **2D 세팅에서는 영역을 거의 전부 열거할 수 있고, MNIST에서는 절대 불가능하다.**
이 비대칭이 2D 세팅을 먼저 하는 실질적 이유다 —
2D에서만 "우리가 샘플링으로 본 영역"과 "실제로 존재하는 영역 전체"를 **직접 비교**할 수 있다.

MNIST에서는 선행연구(Srivastava et al. 2015 포함)와 마찬가지로
**데이터 포인트에서 영역을 샘플링**한다. 그러면 우리가 재는 양은

- ❌ "이 함수의 폴리토프가 몇 개인가"  (함수의 성질)
- ✅ "**데이터 분포를 덮는 데 서로 다른 affine 맵이 몇 개 필요한가**"  (함수 + 분포의 성질)

이 둘은 다른 양이다. 헷갈리면 Stage 1의 숫자를 크게 과대해석하게 된다.
2D에서 두 양을 나란히 재두면, MNIST 숫자를 읽을 때의 보정 감각이 생긴다.

### 1.5 병합 가능성 = 클러스터링, 그리고 거리 척도의 선택

두 영역 r, r'의 affine 맵이 "충분히 비슷하면" 하나로 합칠 수 있다.
합친 개수가 줄어들수록 Ω가 작아진다. 그럼 "비슷하다"를 어떻게 재는가?

거리 척도 세 개를 비교한다. **셋이 서로 다른 것을 재기 때문이다.**

| 척도 | 정의 | 무엇을 재나 | 함정 |
|---|---|---|---|
| **Frobenius** | ‖[A_r\|b_r] − [A_r'\|b_r']‖_F | 파라미터 공간의 유클리드 거리 | 스케일에 민감. 큰 가중치 행이 거리를 지배 |
| **row-wise cosine** | 클래스별 행 방향 각도의 평균 | "판단 방향"이 같은가 | 크기 정보를 버림. 방향은 같고 세기만 다른 영역을 동일시 |
| **logit 차이** | E_x‖A_r·x + b_r − (A_r'·x + b_r')‖ | **실제 행동 차이** | 데이터 분포 x에 의존. 분포 밖에서는 보장 없음 |

**어느 게 "옳은" 척도인가?** 우리 문제 설정이 답을 준다.
제약조건이 `err(⟦P⟧, f_θ) ≤ ε`이므로, ε을 재는 방식과 **일관된** 거리는 logit 차이다.
Frobenius와 cosine은 계산이 싸고 분포에 의존하지 않는 대리 지표(proxy)다.

그래서 예상: **logit 거리가 가장 공격적으로 병합하고(같은 K에서 오차가 낮고),
Frobenius가 가장 보수적일 것이다.** 셋의 차이가 크다면 그 자체가
"이 모델의 파라미터 거리와 행동 거리가 어긋나 있다"는 정보다.
Stage 1에서 이 예상이 맞는지 확인한다.

### 1.6 라우팅 문제 — Stage 1의 정직하지 못한 부분

⚠️ **이걸 명시하지 않으면 Stage 1의 Ω를 과소평가하게 된다.**

설명 P를 실행한다는 건 `⟦P⟧(x) = A_{k(x)}·x + b_{k(x)}`를 계산하는 것이다.
그런데 **`k(x)`를 알려면 어떻게 해야 하나?**

    k(x) = 클러스터( r(x) )        ← r(x)를 알아야 한다
    r(x) = 1[W1·x + b1 > 0]        ← 원본 네트워크의 첫 층을 돌려야 한다

즉 **Stage 1의 P는 원본 신경망을 오라클로 호출한다.** 자립적이지 않다.
정직하게 쓰면:

    Ω(P) = K  +  Ω(라우팅 규칙)

그런데 Stage 1은 앞의 K만 센다. 이건 결함이라기보다 **분업**이다:

- Stage 1: "출력을 만드는 부분"의 복잡도를 잰다 (라우팅은 오라클에 맡김)
- Stage 5(c): 라우팅까지 손으로 짜면서 **정산한다**

Stage 5(c)에서 "신경망 없이 손으로 분류기를 짜면 원본 정확도의 몇 %가 나오는가"를
묻는 이유가 바로 이것이다. 거기가 라우팅 비용이 청구되는 자리다.
그래서 **Stage 1의 Ω는 하한(lower bound)으로 읽어야 한다.**

## Part 2. 인과 개념 (Stage 2·5에서 본격 사용)

### 2.1 ablation (절제)

모델의 일부(유닛, 방향, 컴포넌트)를 **꺼놓고** 출력이 어떻게 변하는지 보는 것.
"이 부품이 없으면 무엇이 망가지는가"를 통해 부품의 역할을 추론한다.

무엇으로 대체하느냐가 결정적이다. 세 가지가 흔히 쓰이고 결론이 달라진다:

| 방식 | 대체값 | 문제 |
|---|---|---|
| zero ablation | 0 | 0이 분포상 극단값이면 "고장냈다"에 가까움 |
| mean ablation | 데이터셋 평균 | 분포 안에 머무름. 보통 더 공정 |
| resample ablation | 다른 입력에서 가져온 값 | 가장 보수적. 상호작용까지 보존 |

Stage 5(a) "특정 컴포넌트를 죽이면 예상한 특정 실패만 일어나는가"에서
어떤 ablation을 쓸지 미리 정하고, **실행 전에 예측을 적어두어야 한다.**

### 2.2 causal importance (인과 중요도)

"이 부품이 이 입력의 계산에 **실제로 기여했는가**"를 나타내는 값.

상관(correlation)과 다르다. 어떤 유닛이 특정 입력에서 크게 활성화되더라도,
그 값이 downstream에 아무 영향을 못 주면 인과적으로는 중요하지 않다.
반대로 활성값은 작은데 뒤에서 크게 증폭되면 중요할 수 있다.

Stage 2에서 SPD가 이 값을 **학습된 함수**로 다룬다. 자세한 건 Part 3.

## Part 3. 파라미터 공간 분해 (Stage 2 예고편)

> Stage 2에서 loss를 한 항씩 뜯으며 다시 확장한다. 여기서는 지도만 그린다.

### 3.1 무엇을 분해하는가

Part 1은 **입력 공간**을 쪼갰다 (폴리토프). Part 3은 **파라미터 자체**를 쪼갠다.

    θ = Σ_c P_c        (파라미터를 컴포넌트들의 합으로 분해)

각 P_c는 θ와 같은 shape의 텐서다. 그리고 각 입력에 대해
**일부 컴포넌트만 인과적으로 중요하다**는 것이 희망이다.

### 3.2 loss 네 항 (Stage 2에서 상세히)

| 항 | 요구하는 것 |
|---|---|
| **faithfulness** | Σ_c P_c 가 원래 θ를 복원해야 한다 |
| **minimality** | 각 입력에 필요한 컴포넌트가 적어야 한다 |
| **simplicity** | 각 컴포넌트가 단순해야 한다 → **낮은 rank** |
| **causal importance** | 컴포넌트별 중요도가 학습된다 (APD의 top-k 대체) |

### 3.3 rank penalty와 Schatten norm

"컴포넌트가 단순하다"를 rank가 낮다는 것으로 정의한다.
그런데 **rank는 미분 불가능한 정수**라 경사하강에 쓸 수 없다.

해결: 특이값(singular value) σ_1, …, σ_n 에 대한 **Schatten p-norm**

    ‖M‖_S(p) = ( Σ_i σ_i^p )^(1/p)

- p=2: Frobenius norm (rank와 무관, 크기만 잼)
- p=1: nuclear norm — **rank의 볼록 완화(convex relaxation)**. 특이값 벡터의 L1이라
  희소성을 유도 → 작은 특이값들이 0으로 눌리며 rank가 실제로 떨어진다
- p<1: 더 공격적이지만 비볼록

L1이 벡터를 희소하게 만드는 것과 정확히 같은 논리를 **특이값 벡터에 적용**한 것이다.
이게 "rank penalty"의 정체다.

### 3.4 APD의 top-k → SPD의 학습된 importance

APD는 "각 입력마다 상위 k개 컴포넌트만 쓴다"고 **하드코딩**했다.
문제:
- k를 손으로 정해야 한다 (입력마다 필요한 개수가 다를 텐데)
- top-k는 미분 불가능 — 경계에서 그래디언트가 끊긴다
- 순위만 보고 크기를 무시한다

SPD는 이걸 **학습되는 importance 함수**로 바꾼다.
입력에 따라 몇 개를 쓸지가 유연해지고, 미분 가능해지며,
"이 입력에는 컴포넌트가 2개만 필요"와 "여기는 7개 필요"를 모델이 스스로 정한다.
Stage 2에서 실제 코드로 확인한다.

## Part 4. grokking과 푸리에 회로 (Stage 3 예고편)

### 4.1 modular addition

`(a + b) mod p` 를 학습시킨다 (보통 p=113). 입력은 one-hot, 출력은 p-way 분류.

### 4.2 grokking

훈련 정확도가 먼저 100%에 도달(암기)하고, **한참 뒤에** 테스트 정확도가
갑자기 100%로 뛰는 현상. 암기 → 일반화로의 상전이.

이 프로젝트에서 중요한 이유: **암기 국면과 일반화 국면의 ε-path가 다를 것이기 때문이다.**
체크포인트를 여러 개 저장해 `(학습시간 t, ε)` 격자를 그리자는 계획이 이걸 노린 것이다.
"Ω가 작아지는 순간"을 시간축에서 직접 볼 수 있다.

### 4.3 푸리에 회로

일반화 이후 모델이 배운 것은 삼각함수 항등식이다.

    cos(w(a+b)) = cos(wa)cos(wb) − sin(wa)sin(wb)
    sin(w(a+b)) = sin(wa)cos(wb) + cos(wa)sin(wb)

즉 a, b를 소수의 주파수 w로 원 위에 올린 뒤, **각도를 더하고**, 다시 읽어낸다.
Ω = 사용된 주파수 개수 (보통 5개 내외). 이게 **압축이 확실히 성공한 사례**다.

Stage 3이 대조군인 이유: 여기서 ε-path가 어떤 모양인지 봐야
Stage 1의 곡선이 "다르다"고 말할 자격이 생긴다.

## Part 5. 용어 빠른 참조

| 용어 | 한 줄 정의 |
|---|---|
| activation pattern / binary code | 입력 x에 대해 각 ReLU 유닛의 켜짐/꺼짐을 적은 비트 벡터 `r(x)` |
| gate matrix `D(r)` | `diag(r)`. r을 고정하면 ReLU를 대체하는 대각행렬 |
| effective linear map `A_r` | `W2·D(r)·W1`. 영역 r에서 신경망과 동일한 선형 부분 |
| offset `b_r` | `W2·D(r)·b1 + b2`. affine 맵의 절편. **빼먹지 말 것** |
| region / polytope | 같은 활성 패턴을 갖는 입력들의 집합. 반공간들의 교집합 |
| hyperplane arrangement | 초평면들이 공간을 자르는 방식. hidden 1층 영역 구조가 정확히 이것 |
| ε-path | 허용 오차 ε에 따른 최소 복잡도 Ω(ε)의 곡선. **이 프로젝트의 산출물** |
| simulation relation | 내부 상태끼리의 대응. 입출력 일치보다 강한 조건 |
| routing | 입력 x가 어느 클러스터에 속하는지 결정하는 문제. Stage 1에서는 오라클에 맡김 |
| ablation | 부품을 끄고 무엇이 망가지는지 보는 것 (zero / mean / resample) |
| causal importance | 부품이 계산에 실제로 기여한 정도. 상관과 다름 |
| faithfulness | 분해된 컴포넌트의 합이 원본 파라미터를 복원하는가 |
| Schatten p-norm | 특이값 벡터의 p-norm. p=1(nuclear)이 rank의 볼록 완화 |
| grokking | 암기 후 한참 뒤 일반화가 갑자기 일어나는 상전이 |
